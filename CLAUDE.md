# Scale Shift: notes for Claude Code

True-size world map with a timeline from 1 BC to today. Drag countries, states and historical empires and see their real size. Next.js 16 (App Router, Cache Components on), TypeScript, Tailwind 4, d3-geo. No map tiles or API keys.

**Read `docs/PROJECT.md` at the start of any new task.** It has the goal, decisions, design system, quality bar and roadmap.

## Team: shared ownership
Anthony (Mac) and Evan (Windows) both own the whole project. Either can change any file and ship it. Neither needs the other's approval, but big changes get a heads-up first (see below).

## "Ship it" means
1. `git switch main && git pull`
2. `git switch -c <short-branch-name>` (e.g. `add-aztec-comparison`)
3. Make the change.
4. `npm run lint && npm run typecheck && npm run build` must all pass (plus `npm run check:data` if anything in `public/data` or `scripts/build-data.mjs` changed). Fix failures; never skip checks.
5. Commit with a clear message, then `git push -u origin <branch>`.
6. `gh pr create` with a short summary: what changed, why, and how to see it.
7. `gh pr checks --watch` until CI passes. If it fails, fix it and push again.
8. `gh pr merge --squash --delete-branch`
9. `git switch main && git pull`

If the user says "open it but don't merge", stop after step 7 and give them the PR link.

**Big changes** (layout or visual design, the map engine in `lib/geo.ts` or `components/map/MapCanvas.tsx`, the data pipeline, dependencies, anything that deletes features): open the PR but don't merge. Tell the user to share the link with the other owner first.

## Avoid collisions
- Before starting, run `gh issue list` and `gh pr list`. If someone else is already working in the same files, warn the user before editing.
- Suggest opening a GitHub issue for any task bigger than a few minutes and assigning it to whoever is doing it.
- Never push directly to `main`. Never force-push. Never rewrite shared history.
- On a merge conflict: merge `main` into the branch, resolve it keeping both people's intent, rerun the checks.

## Read first (technical)
- This is Next.js 16. APIs differ from older versions: check `node_modules/next/dist/docs/` before using a Next API you're unsure of.
- `params` is a Promise. `dynamicParams` and similar segment configs are not allowed with Cache Components.
- Dynamic pages (`app/compare/[slug]`, `app/history/[id]`) wrap their content in `<Suspense>` so navigation stays instant. Keep that pattern.

## Where things live
- `content/*.ts`: all copy, comparison pages, featured empires, lineage. Change words here, not in components.
- `lib/geo.ts`: true-size math. `relocate()` rotates shapes on the sphere. Never shift shapes in flat pixels.
- `components/map/*`: the map app (MapApp orchestrates; MapCanvas draws; OverlayPanel, TimeDock, SearchBox).
- `public/data/`: generated by `npm run data` from `data-src/` (not committed). Don't hand-edit. Name aliases live at the top of `scripts/build-data.mjs`.
- `app/api/submit/route.ts`: form endpoint (local JSON file, optional webhook or Resend email).
- `docs/PROJECT.md`: project brief, decisions and roadmap. Update it when a decision changes.

## Commands
- `npm run dev`: local site at http://localhost:3000
- `npm run lint && npm run typecheck && npm run build`: must all pass before a PR (CI runs the same on GitHub)
- `npm run check:data`: after any data change
- `npm run test:e2e`: browser tests (needs `npm run start` running and `npx playwright install chromium` once)

## Rules
- Entity ids are slugs from `public/data/index.json`; years are snapshot years (`-1` = 1 BC, `2026` = today).
- Historical data is GPL-3.0 (historical-basemaps). Keep the credits in the footer and on /about.
- Antarctica is excluded on purpose: Mercator can't draw a shape that surrounds a pole.
- Never commit secrets. `.env*` files are ignored; keys go in Vercel's environment variables.
- Original work only: thetruesize.com inspired the idea, but never copy its text, name, design or code.

## Windows notes (Evan)
- Use PowerShell. If npm fails with "running scripts is disabled", run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once.
- Line endings are handled by `.gitattributes`; keep `git config --global core.autocrlf true`.
- The git email must exactly match the email on the GitHub account, or Vercel won't deploy the change.
